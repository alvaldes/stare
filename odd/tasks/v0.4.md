# Stare v0.4: interacción de canvas, toolbar configurable y editor de capturas

Objetivo: cerrar la tanda de issues y features que el owner pidió el 2026-11-22 sobre cuatro áreas — zoom y cursores del canvas, selección múltiple, toolbar configurable, persistencia por defecto y editor de capturas. El alcance es de varias sesiones: este documento fija las specs, el orden de ataque y qué queda explícitamente para después.
Rama: una por unidad de entrega, desde `main` (`fix/<área>` o `feat/<área>`). Runner: `swift test` + `Scripts/bundle.sh release install` + capturas reales (`screencapture -l`) cuando el cambio se ve. Entrega: `main-direct` para arreglos chicos y verificados; PR para lo que toque contratos o supere ~400 líneas.

## Specs

S1. "Se debe poder hacer zoom en el whiteboard con cmd+mouse_scroll" — con la pizarra abierta, ⌘ + rueda del mouse (o scroll de trackpad) hace zoom sobre el contenido; sin ⌘ el scroll no cambia el zoom. El zoom ya existe por pinch y por ⌘+/⌘−/⌘0, y el estado del zoom es el mismo: no se agrega un segundo modelo de zoom.

S2. "Cada tool debe tener un cursor personalizado dentro de lo posible" — cada herramienta del modo dibujo muestra un cursor propio y distinguible (lápiz, marcador, flecha, rectángulo, elipse, texto, número, selección, borrador, láser, blur, puntero), usando cursores de sistema o `NSCursor` dibujados por la app. "Dentro de lo posible": si un cursor no aporta distinción o no puede construirse sin arte nuevo, se documenta y se deja el cursor por defecto.

S3. "en el whiteboard cuando se hace pam con space+mouse se debe mostrar el cursor de la mano como que agarrando para que se note que se esta haciendo pam. Lo mismo para el zoom y el cursor." — con space apretado y arrastre, el cursor es la mano cerrada (agarrando) y vuelve a la mano abierta al soltar; durante el zoom el cursor es el de zoom (lupa con + / −), no el de la herramienta. El cursor vuelve al de la herramienta al terminar el gesto.

S4. "En el toolbar debe aparecer despues de la 'x' un espacio como este '⠇⠇' ... para ayudar al usuario a mover el toolbar. Ademas si se da click derecho sobre esto se resetea la posicion." — después del botón de cerrar aparece una zona de agarre visible con patrón de puntos en braille (`⠇⠇`); arrastrarla mueve el toolbar; el click derecho sobre esa zona devuelve el toolbar a su posición por defecto (la preferencia de anclaje ya existente). Antes de implementar se investiga cómo lo hacen otras apps del rubro con este estilo y se anota en el Log.

S5. "si limpio con esc y despues hago cmd+z se debe restaurar lo que se limpio" — el borrado total por Escape entra al historial global: ⌘Z lo restaura completo (todas las marcas de todos los displays/páginas que borró) y ⇧⌘Z lo vuelve a borrar.

S6. "el crop no se marca como los tools en el editor de capturas. si se selecciona el crop se debe de desmarcar el tool que este y marcar este porque tambien es un tool." — en el editor de capturas el crop participa del mismo estado de herramienta seleccionada que el resto: al elegir crop se desmarca el tool activo, y al elegir cualquier tool se desmarca crop. Un solo estado, no dos.

S7. "Cuando hago crop en el editor de capturas una vez que hago el recorte no puedo editarlo como una edicion normal donde tomo los bordes y los muevo... O sea no puedo regresar si no es un redo." — el recorte aplicado queda re-editable como una edición: se pueden volver a tomar sus bordes y ajustarlo. Alcance de esta versión, decidido por el owner: si re-editar el recorte es demasiado, se arregla solo lo de S6 y el resto — re-edición, más las features útiles de shottr.cc y cleanshot.com — queda documentado como backlog para otras versiones.

S8. "en el modo dibujo y en el whiteboard cuando estoy con el tool 'v'-puntero solo selecciona si hago click sobre el elemento pero que pasa si hago un arrasre como una seleccion multiple o solo sobre un area deberia de marcarme todos los elementos de esa area. Tambien si tengo algo selecionado y quiero seleccionar otro junto con ese puedo hacerlo con shift." — con el tool puntero, arrastrar sobre un área selecciona todas las marcas que intersecta (marquesina visible), y ⇧+click agrega o quita una marca de la selección actual. Referencia visual: presentifyapp.com/videos/annotate-compressed.mp4 desde el segundo 9.

S9. "las configuraciones que estan en pointer hightlight ahora mismo son las que tienen que estar por defecto" — el estado actual del owner para Pointer Highlight (forma, tamaño, color, banda, glow, borde, opacidad, animación) pasa a ser el valor de fábrica de la app, sin cambiar el comportamiento del panel.

S10. "En las opciones del toolbar se debe poder personalizar que tools mostrar y cuales ocultar y reorganizar a gusto la barra" — desde Settings se elige qué herramientas aparecen en el toolbar y en qué orden; el toolbar dibuja exactamente eso, sin huecos ni ítems fantasma, y la elección persiste.

S11. "Por default se debe se tener activo en settings que se persista lo que se dibuje y las pages del whiteboard sin importar si la app se cierra o si se cierran los modos. Si el usuario quiere este comportamiento se puede desactivar pero por defecto esto persiste todo hasta un reinicio de la pc." — por defecto, marcas y páginas sobreviven a cerrar la app y a salir de los modos, hasta un reinicio de la máquina; un interruptor en Settings permite desactivarlo y volver al comportamiento efímero.

S12. "En settings debe de haber una opcion para que se configure si se quiere el toolbar horizontal o vertical y arriba, abajo, izquierda o derecha." — Settings ofrece orientación (horizontal/vertical) y borde (arriba/abajo/izquierda/derecha) del toolbar; el toolbar respeta ambos y persiste la elección, y la posición por defecto del reset de S4 es la que fijan estas dos preferencias.

S13. Nada existente se rompe: la suite sigue verde, `swift build -c release` compila, los atajos y las preferencias existentes siguen funcionando, y ningún cambio pide permisos nuevos.
